# Week 10 — Advanced SOC Exercises

## Exercise 03: IOC Investigation & Enrichment

**Date:** 25 September 2026
**Platform:** Windows Server 2025
**Telemetry:** Sysmon → Splunk Universal Forwarder → Splunk Enterprise
**Splunk Index:** `soc_logs`
**Sourcetype:** `XmlWinEventLog:Microsoft-Windows-Sysmon/Operational`
**IOC Investigated:** `20.42.179.192`

---

## Objective

Investigate an IP address observed in existing Windows endpoint telemetry and determine:

* Where the IOC appeared locally
* Which process was responsible for the network activity
* Whether PID reuse affected attribution
* Which parent processes were involved
* Whether the process generated additional file, registry, or process activity
* What external enrichment indicates
* Whether the available evidence supports a malicious or benign assessment

The investigation used existing telemetry only. No new suspicious activity was intentionally generated.

---

## 1. Initial IOC Discovery

The IP address `20.42.179.192` was selected from existing Sysmon Event ID 3 network telemetry.

The initial search identified **13 network connection events** to:

`20.42.179.192:443`

The events were associated with two processes:

* `svchost.exe` — PID 4968 — 1 connection
* `taskhostw.exe` — PID 4540 — 12 connections

All observed connections were TCP connections to port 443.

---

## 2. PID Reuse Investigation

PID `4540` was investigated to determine whether the network activity could be attributed reliably using the PID alone.

The investigation identified two different process instances using PID 4540.

### Earlier process instance

**Time:** `2026-09-25 10:31:21.572`

* Image: `ROUTE.EXE`
* Command Line:
  `C:\Windows\System32\route.exe DELETE 169.254.169.123/32`
* PID: `4540`
* ProcessGuid: `{12dcad69-4d79-6ab6-8300-000000006b00}`
* Parent: `EC2Launch.exe`
* Parent PID: `3816`

### Later process instance

**Time:** `2026-09-25 10:33:26.744`

* Image: `taskhostw.exe`
* Command Line: `taskhostw.exe`
* PID: `4540`
* ProcessGuid: `{12dcad69-4df6-6ab6-fd00-000000006b00}`
* Parent: `svchost.exe`
* Parent PID: `1712`

This demonstrated that PID 4540 was reused.

Therefore, PID alone could not reliably identify which process generated the IOC traffic.

The Sysmon `ProcessGuid` provided the required process-instance correlation.

---

## 3. IOC Process Correlation

The 12 IOC connections generated by the later PID 4540 instance were associated with:

**Process:** `taskhostw.exe`

**PID:** `4540`

**ProcessGuid:**

`{12dcad69-4df6-6ab6-fd00-000000006b00}`

**User:** `SYSTEM`

The IOC traffic occurred between approximately:

`2026-09-25 10:33:45` and `10:33:54`

All 12 IOC connections used TCP port 443.

This confirms that the `20.42.179.192` network activity was associated with the later `taskhostw.exe` process instance rather than the earlier `ROUTE.EXE` instance.

---

## 4. Parent Process Investigation

The parent of the identified `taskhostw.exe` process was:

`C:\Windows\System32\svchost.exe`

Command line:

`C:\Windows\system32\svchost.exe -k netsvcs -p -s Schedule`

The parent process details were:

* PID: `1712`
* ProcessGuid: `{12dcad69-4d75-6ab6-2500-000000006b00}`
* User: `SYSTEM`
* Parent: `services.exe`

The resulting process chain was:

```text
services.exe
    ↓
svchost.exe
-k netsvcs -p -s Schedule
    ↓
taskhostw.exe
    ↓
Outbound TCP/443 connections
```

This provides context that the network activity occurred within a Windows scheduled-task/service process chain.

---

## 5. Broader Network Activity for the Process

The exact `taskhostw.exe` ProcessGuid was searched across all available Sysmon Event ID 3 network events.

The search returned **42 outbound TCP/443 connections**.

The connections were distributed across seven destination IP addresses:

| Destination IP    | Connections | Port |
| ----------------- | ----------: | ---: |
| `172.215.188.225` |          13 |  443 |
| `20.42.179.192`   |          12 |  443 |
| `85.210.193.152`  |           8 |  443 |
| `40.84.97.4`      |           6 |  443 |
| `172.215.188.232` |           1 |  443 |
| `4.247.188.224`   |           1 |  443 |
| `57.155.104.224`  |           1 |  443 |

The IOC represented one destination within a broader pattern of outbound HTTPS activity from the same process instance.

---

## 6. Process Activity Checks

The exact `taskhostw.exe` ProcessGuid was checked for additional Sysmon activity.

The following search returned **0 events**:

* Event ID 11 — File creation
* Event ID 12 — Registry object creation/deletion
* Event ID 13 — Registry value modification
* Event ID 14 — Registry key/value rename

No corresponding file or registry activity was observed for this ProcessGuid in the available telemetry.

A separate search for child processes associated with the parent `svchost.exe` ProcessGuid also returned **0 events**.

These results indicate that the available Sysmon telemetry did not show additional file, registry, or process activity associated with the investigated process chain.

---

## 7. External IOC Enrichment

The IP address `20.42.179.192` was checked against external IP reputation information.

The enrichment associated the address with Microsoft infrastructure, including:

* Organization/ISP: Microsoft Corporation
* ASN: AS8075
* Domain: `microsoft.com`
* Usage type: Data Center / Web Hosting / Transit
* Country: United States

The reputation data also contained a small number of abuse reports.

IP reputation alone is not sufficient to establish that a connection from a Windows system was malicious. The address must be evaluated together with the local process, timing, destination behavior, and other telemetry.

---

## 8. Analyst Assessment

The investigation established that `20.42.179.192` appeared in 12 network connections generated by a specific `taskhostw.exe` process instance running as `SYSTEM`.

The process was launched through the following chain:

```text
services.exe
    ↓
svchost.exe -k netsvcs -p -s Schedule
    ↓
taskhostw.exe
```

The process generated 42 outbound TCP/443 connections to seven destinations.

The use of `ProcessGuid` was important because PID 4540 had previously belonged to a different process, `ROUTE.EXE`.

No additional process, file creation, or registry activity was identified for the investigated process through the available Sysmon telemetry.

The external enrichment identifies `20.42.179.192` with Microsoft infrastructure, while also showing limited abuse-report history. This reputation information is contextual evidence rather than proof of compromise.

### Disposition

**Benign / Expected Windows System Activity — based on available telemetry**

This disposition is limited to the evidence available in the SOC lab. It does not establish that every connection to the IP is inherently safe or that the destination can never be abused.

---

## 9. Telemetry Limitations

Several limitations were identified during the investigation:

1. PID values can be reused by different process instances.
2. ProcessGuid provides stronger process-instance correlation than PID alone.
3. The investigated network events did not provide useful destination hostnames for the IOC connections.
4. Absence of Event IDs 11, 12, 13, or 14 does not prove that no other system activity occurred outside the available telemetry.
5. IP reputation should not be treated as a standalone determination of maliciousness.
6. The investigation was limited to the telemetry currently available in the `soc_logs` index.

---

## 10. Key SOC Analyst Lessons

### 1. Never rely on PID alone

A PID can be reused after a process exits. ProcessGuid should be used when available to distinguish process instances.

### 2. IOC investigation requires context

Finding an IP address in network telemetry is only the starting point. The analyst must determine:

* Which process contacted it
* Which user executed the process
* What parent process started it
* What other activity occurred
* Whether the behavior is consistent with expected system activity

### 3. Reputation is evidence, not a verdict

An IP reputation result can provide useful context, but it should be combined with endpoint telemetry and process behavior.

### 4. Absence of telemetry is not proof of absence

A zero-event search means that the configured and available telemetry did not record the requested activity. It should not automatically be interpreted as proof that the activity never occurred.

### 5. Process correlation improves investigation quality

The investigation progressed from:

```text
IOC → PID → ProcessGuid → Process → Parent → Process chain → Related activity
```

This is a practical SOC investigation workflow for endpoint network indicators.

## Conclusion

The IOC investigation demonstrated how a SOC analyst can move from an observed network indicator to process-level attribution and contextual analysis.

The key finding was that PID 4540 was reused by two separate processes. ProcessGuid correlation established that the 12 connections to `20.42.179.192` belonged to the later `taskhostw.exe` process instance.

The broader investigation identified 42 outbound HTTPS connections from that same process to seven destinations, while no additional process, file, or registry activity was observed for the exact ProcessGuid in the available Sysmon telemetry.

The investigation therefore provides a documented example of IOC enrichment, process correlation, PID-reuse handling, and evidence-based SOC disposition.
