# Detection 03 — Suspicious User-Directory Process Creation

## 1. Overview

This detection identifies executable processes launched from a user-writable directory, specifically under `C:\Users\`, when the parent process is Windows PowerShell.

Processes executing from user directories can be legitimate, but they can also indicate suspicious activity because user-writable locations are commonly used to store and execute downloaded or staged files.

This detection demonstrates a SOC workflow of:

**Telemetry → Detection → Investigation → False Positive Identification → Tuning → Validation**

---

## 2. Lab Architecture

The detection was tested in the SOC Analyst Home Lab using:

- Windows Server 2025
- Sysmon
- Splunk Universal Forwarder
- Splunk Enterprise
- Splunk index: `soc_logs`
- Sysmon Event ID 1 — Process Creation
- Splunk receiving port: TCP 9997

Telemetry flow:

**Windows Server 2025 → Sysmon → Splunk Universal Forwarder → TCP 9997 → Splunk Enterprise → `soc_logs` → SPL Detection**

---

## 3. Objective

The objective is to identify potentially suspicious processes that:

1. Are created from a user-writable directory under `C:\Users\`
2. Are launched by Windows PowerShell

The detection should provide enough context for a SOC analyst to investigate the process, user, command line, and parent process.

---

## 4. Sysmon Event Source

### Sysmon Event ID 1 — Process Creation

Event ID 1 records process creation activity and provides important investigation fields such as:

- Image
- CommandLine
- User
- ParentImage
- ParentCommandLine
- Process ID
- Parent Process ID

These fields allow an analyst to reconstruct the process execution chain.

## 5. Initial Telemetry Discovery

The first attempt to search directly for `EventID=1` returned no results because the Sysmon Event ID was contained inside the raw XML and was not automatically parsed by Splunk.

The following SPL was used to extract the Event ID:

```spl
index=soc_logs
| rex field=_raw "<EventID>(?<EventID>\d+)</EventID>"
| stats count by EventID
| sort EventID

The search returned the following telemetry:

| Event ID | Count |
| -------- | ----: |
| 1        |  9731 |
| 3        |   425 |
| 5        |  1369 |
| 16       |     4 |

This confirmed that Sysmon Process Creation telemetry was being successfully ingested.

6. Initial Process Investigation

The Event ID 1 process telemetry was investigated to understand normal activity before creating the detection.

A process-frequency query was used:

index=soc_logs
| rex field=_raw "<EventID>(?<EventID>\d+)</EventID>"
| search EventID=1
| rex field=_raw "<Data Name='Image'>(?<Image>[^<]*)</Data>"
| stats count by Image
| sort -count
| head 30

The investigation showed that many Event ID 1 events were generated by legitimate Windows and Splunk Universal Forwarder activity.

Examples included:

splunk-powershell.exe
splunk-admon.exe
splunk-netmon.exe
splunk-regmon.exe
backgroundTaskHost.exe
svchost.exe
RuntimeBroker.exe

This demonstrated that alerting on every process creation event would generate excessive noise.

7. Detection Logic

The detection focuses on the following process chain:

Sysmon Event ID 1
        ↓
Process Image under C:\Users\
        ↓
Parent Image is Windows PowerShell
        ↓
Potentially Suspicious Process

The detection considers this behavior suspicious because a process launched from a user-writable directory by PowerShell can be associated with downloaded, staged, or script-driven execution.

The behavior is not automatically malicious and requires analyst investigation.

8. Initial Detection Query

The initial detection query was:

index=soc_logs
| rex field=_raw "<EventID>(?<EventID>\d+)</EventID>"
| search EventID=1
| rex field=_raw "<Data Name='Image'>(?<Image>[^<]*)</Data>"
| rex field=_raw "<Data Name='CommandLine'>(?<CommandLine>[^<]*)</Data>"
| rex field=_raw "<Data Name='User'>(?<User>[^<]*)</Data>"
| rex field=_raw "<Data Name='ParentImage'>(?<ParentImage>[^<]*)</Data>"
| rex field=_raw "<Data Name='ParentCommandLine'>(?<ParentCommandLine>[^<]*)</Data>"
| search Image="*\\Users\\*" ParentImage="*\\WindowsPowerShell\\*"
| eval Severity="Medium"
| table _time host Image CommandLine User ParentImage ParentCommandLine Severity
| sort - _time

9. Initial Detection Result

The initial query returned 14 events.

All 14 events matched the detection condition:

Process image located under C:\Users\
Parent process was Windows PowerShell
Sysmon Event ID 1

The events therefore required investigation before being classified as suspicious.

EC2AMAZ-OOOVRCR\Administrator

Observed commands included Sysmon configuration operations such as:

"C:\Users\Administrator\Downloads\Sysmon\Sysmon64.exe" -c

and:

"C:\Users\Administrator\Downloads\Sysmon\Sysmon64.exe" -c C:\Users\Administrator\Downloads\Sysmon\sysmon-config.xml

12. False Positive Identification

The investigation determined that the 14 events represented legitimate Sysmon installation and configuration activity.

The process:

Sysmon64.exe

was intentionally executed from the user's Downloads directory during the SOC lab setup.

The activity was therefore classified as a known-good administrative action rather than malicious execution.

This is an important SOC analyst lesson: a detection match is an investigation starting point, not proof of compromise.

13. Detection Tuning

Because the initial detection generated known-good Sysmon configuration events, the detection was tuned to exclude Sysmon64.exe.

The tuned query uses:

| where NOT match(lower(Image), "\\\\sysmon64\\.exe$")

This removes known-good Sysmon configuration activity while preserving other executable activity from user directories launched by PowerShell.

Tuned Detection Query
index=soc_logs
| rex field=_raw "<EventID>(?<EventID>\d+)</EventID>"
| search EventID=1
| rex field=_raw "<Data Name='Image'>(?<Image>[^<]*)</Data>"
| rex field=_raw "<Data Name='CommandLine'>(?<CommandLine>[^<]*)</Data>"
| rex field=_raw "<Data Name='User'>(?<User>[^<]*)</Data>"
| rex field=_raw "<Data Name='ParentImage'>(?<ParentImage>[^<]*)</Data>"
| rex field=_raw "<Data Name='ParentCommandLine'>(?<ParentCommandLine>[^<]*)</Data>"
| search Image="*\\Users\\*" ParentImage="*\\WindowsPowerShell\\*"
| where NOT match(lower(Image), "\\\\sysmon64\\.exe$")
| eval Severity="Medium"
| table _time host Image CommandLine User ParentImage ParentCommandLine Severity
| sort - _time
14. Tuned Detection Result

After tuning, the detection was executed again over the available 24-hour time range.

The result was:

No results found.

The previously identified 14 known-good Sysmon events were successfully excluded.

15. Severity

Severity: Medium

The behavior is classified as Medium because execution of a process from a user-writable directory by PowerShell can be suspicious, but the behavior alone does not prove malicious activity.

Severity could be increased if additional indicators were present, such as:

Suspicious command-line arguments
Encoded PowerShell commands
Unknown executable
Unusual parent process
Network connections
Persistence activity
Known malicious hash
Evidence of credential access
16. Potential False Positives

Potential legitimate matches include:

Software installation
Administrative scripts
Developer tools
System utilities
IT troubleshooting
Security tools
User-installed applications
Lab or testing activity

Known-good applications should be excluded carefully to reduce alert fatigue without hiding genuinely suspicious behavior.

17. Investigation Workflow

When this detection triggers, a SOC analyst should:

Step 1 — Identify the process

Review:

Image
CommandLine

Determine what executable was launched.

Step 2 — Identify the user

Review:

User

Determine which account executed the process.

Step 3 — Investigate the parent

Review:

ParentImage
ParentCommandLine

Determine why PowerShell launched the process.

Step 4 — Review the timeline

Look for related:

Process creation events
Network connections
File creation events
Authentication activity
Other PowerShell activity
Step 5 — Validate the executable

Where appropriate, investigate:

File hash
File location
Digital signature
Reputation
Known software ownership
Step 6 — Determine the disposition

Classify the event as:

Benign
Suspicious
Malicious
Requires further investigation
